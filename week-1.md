# Week 1 Learning Log

## Testing is Fundamental

Testing is one of the fundamentals in developing products and projects. It starts from researching and planning, and continues till evaluating feedback from customers after release.

| Stage | Testing Role |
|-------|--------------|
| Research & Planning | Define test strategy and scope |
| Design | Plan test cases and validation approach |
| Development | Unit testing, early bug detection |
| Testing Phase | Full testing cycle, bug reporting |
| Release | Final smoke testing, production readiness |
| Post-Release | Monitor production, regression testing, hotfix validation |

## Waterfall vs Agile - Key Differences

I already knew some developing models, but got reminded about their principles — Waterfall and Agile.

| Aspect | Waterfall | Agile |
|--------|-----------|-------|
| Flow | Sequential, one phase at a time | Iterative sprints (1-4 weeks) |
| Changes | Difficult mid-project | Easy to adapt quickly |
| Testing | After development phase | Continuous throughout sprints |
| Best for | Stable requirements | Changing requirements |

---

## Waterfall Model Details

**Waterfall** is a linear development process where each phase must complete before the next begins. Like a chain connecting each piece by piece — everything is linked together.

**Phases:** Requirements → Design → Development → Testing → Deployment → Maintenance

**How it works:**
- Each phase pulls the next phase forward
- Everyone waits for the previous phase to finish
- Testing happens only after all coding is done
- Test plan is created early but execution is late

**Weak Points:**
- If one link breaks (like major bugs in testing), the whole chain stops
- Hard to go back and change things
- Problems found late are expensive to fix
- If requirements change, the chain breaks
- No working software until the very end

**Testing in Waterfall:**
- Entire testing phase happens after all coding is done
- If major bugs are found, it delays the whole project
- Changes are expensive to implement

**Best for:** Stable projects like banking systems, hardware, where requirements don't change.

## Agile - Key Points

The main points in Agile model are communication with each other, the feedback and be able to change something in a short term, be interchangeable with each other in your team.

**How Agile Works:**
- Short cycles called sprints (1-4 weeks)
- Team plans, develops, tests together in same sprint
- Every sprint delivers working software
- Users/clients see progress every sprint
- Easy to change direction based on feedback

**Agile Sprint Cycle:**
1. Plan what to build
2. Daily team meetings
3. Developers code + QA tests simultaneously
4. Sprint review with clients
5. Team talks about what went well/bad (retrospective)

**Testing in Agile:**
- QA works with developers during development, not after
- Bugs caught immediately and fixed quickly
- Continuous feedback from users
- Less waiting, more action

| Agile Principle | What it Means |
|-----------------|---------------|
| Communication | Team talks constantly |
| Feedback | Users/clients give input fast |
| Flexibility | Change direction quickly |
| Cross-functional | Everyone can do everything |
| Iterative | Small pieces, not big bang |
| Quality over documentation | Working software matters more |

---

## Precision in Development

The main points are to be precise in all developing stages. Accuracy matters everywhere — in testing, documentation, communication, and feedback collection.

| Where Precision Matters | Why |
|-------------------------|-----|
| Test Cases | Clear expectations |
| Bug Reports | Easy to fix |
| Documentation | No confusion |
| Communication | Fewer mistakes |
| Requirements | Know what to build |

---

## Summary

Testing connects everything — from planning to release to feedback. Development models guide how we work. Waterfall is a rigid chain — strong if requirements stay the same, but breaks under pressure. Agile is flexible and adaptive. Precision in every stage prevents problems and costs.
